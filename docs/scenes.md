## 1. 单局流程与区域结构

### 1.1 单局流程

| 区域 | 主题 | 房间数 | 内容重点 | Boss |
| --- | --- | --- | --- | --- |
| 1. 青篁岭·竹坞客栈 | 教学、竹海夜雨、客栈 | 8–10 | 基础操作、第一批装备 | 焦面掌柜 |
| 2. 药王谷·腐草洞 | 毒/药人 | 10–12 | 状态异常、垂直探索 | 药人母 |
| 3. 寒山寺·沉钟楼 | 机关、钟声 | 12–14 | 陷阱、精英群 | 守钟僧 |
| 4. 烬心地宫 | 灯焰/终局 | 8–10 | 综合考验、剧情揭示 | 无相 |

- 关卡为手工制作、布局固定，地形、机关与主要敌人站位每局一致，方便玩家记忆路线与积累应对经验。
- 每个区域采用"关键路径 + 1–2 条支路"的结构，支路高风险高回报。
- 区域之间有传送门，可选择路线分支（例如：洞窟走"毒池捷径"或"矿道精英路"）。
- 每局开始可携带 1 把初始武器（解锁后可自选 2 选 1）。
- 已开启的捷径与区域检查点永久保留，重启一局时减少重复跑图。

## 2. 关卡设计（固定地图）

### 2.1 核心原则

- 关卡由手工设计，布局、地形、机关与主要敌人站位在每次游戏中保持一致。
- 玩家死亡后重走熟悉的路线，依靠记忆、路线规划与操作熟练度推进，而不是每局重新适应随机地形。
- 固定不等于单调：重复可玩性由装备掉落、词缀组合、精英词缀、事件选择、热度难度与剧情解锁承担。
- 每个区域 8–14 个房间（每间 1–3 屏，横向滚动），单区域游玩时长约 15–25 分钟。
- 每个区域设置 2–3 个醒目的地标（竹坞客栈招牌、寒山巨钟、烬心灯），帮助玩家建立空间记忆。

### 2.2 制作流程（Tiled）

1. **白盒**：用纯色地块搭建路线、跳跃间距与战斗空间，先在练习场验证手感。
2. **走查**：确认主路径可通关、支路可返回、没有死路和卡点。
3. **战斗布置**：放置敌人、机关、补给，控制战斗密度与休息节奏。
4. **美术层**：替换地块与装饰，完成光照与背景，保证战斗信息可读。
5. **校验**：`tools/validate_data.py` 检查出生点、出口、传送、门锁与可达性。
6. **版本化**：`.tmx` 与图集全部入库，地图改动通过提交记录追溯与回滚。

### 2.3 地图结构与引导

- 线性主路线 + 少量支路（宝箱、秘密、商店）；用场景视觉引导，而不是箭头。
- Boss 前的单向捷径可在通关后永久开启，后续单局减少重复跑图（由 meta 解锁）。
- 每个区域入口设置检查点灯龛，死亡后从区域起点重来；Boss 前设置独立的重试点。
- 大地图 UI 显示已探索房间、出口类型与已开启捷径，未探索区域只显示大致方向。
- 秘密房间位置固定，通过可破坏墙体或隐藏通道进入，奖励稀有装备或剧情碎片。

### 2.4 每局变化来源（不改变地图布局）

| 变化项 | 说明 |
| --- | --- |
| 装备与词缀 | 掉落品质、词缀、武器种类随机，决定本局流派 |
| 精英词缀 | 精英敌人附加随机词缀（狂暴/护盾/吸血/召唤） |
| 局内事件 | 固定位置的事件点提供 2–3 种选择（交易/赌博/诅咒） |
| 烬屑与商店 | 货郎货品与价格浮动 |
| 灯焰热度 | 妖物强化与附加规则（药瓶减少、时限等） |
| 剧情推进 | 随回环次数解锁新对话、新区域入口与真结局条件 |

### 2.5 为什么选择固定地图

- 降低学习成本：玩家能专注于战斗与构筑，而不是迷路。
- 强化熟练度成长：路线优化、资源规划、Boss 招式记忆构成"玩家自身的成长"。
- 与永久成长互补：余烬解锁带来数值与内容成长，固定关卡提供稳定的练习场。
- 内容质量可控：手工关卡的节奏、演出与战斗密度优于程序拼接，便于反复打磨。
- 风险与对策：固定地图可能降低新鲜感，需要靠变化来源、隐藏要素、后续章节扩展与热度模式延长生命周期。

### 2.6 房间与地块规范

- 地块尺寸 16×16；角色碰撞体约 14×30。
- 房间支持 1–3 屏横向滚动；相机跟随玩家并夹在房间世界边界内，窄于 480 px 时固定居中。
- 图层：`background`、`terrain`、`platform_one_way`、`hazard`、`decor`、`entities`、`foreground`。
- 出生点、敌人点、宝箱点用 Tiled 对象层配置，pytmx 读取。
- 每张地图必须有 `player_spawn` 与至少一个 `exit`，由 `validate_data.py` 校验。

### 2.7 装饰与演出

- 装饰与粒子（竹叶飘落、流萤、灯灰）按固定配置呈现，保证同一房间每次的环境表现一致。
- opensimplex 仅用于非玩法层的氛围微变化，使用固定配置，不影响空间记忆。
- "回环侵蚀"等场景变化改为剧情触发的固定剧本（例如特定回环次数后某段墙体破裂），不随机改变布局。

### 2.8 第一关现状（M2 已实现：多房间探索地图）

第一关已从单屏白盒升级为 **10 个房间的固定图结构**（`game/scenes/bamboo_world.py` 的 `build_world()`）；`RunScene` 以相机卷轴逐房间渲染。场景美术全部由 pygame 图元程序化绘制，没有使用外部素材，也未直接移植开源项目代码（仅参考其长地图与密室结构思路）。旧的单屏实现 `game/scenes/inn_stage.py` 保留作历史参考，已不接入游戏流程。

#### 2.8.2 相机、舆图与状态

- 相机横向跟随玩家，带 24 px 前瞻，并夹在房间世界边界内；当前房间先绘制到 `width×270` 的世界表面，再按相机裁剪出 480×270，HUD、前景竹叶与暗角固定在屏幕坐标。
- `M` 打开全局舆图：显示已探索、已清空、当前房间、房间短名与灯锚图标，未探索的相邻房间以暗色节点提示；舆图打开时暂停游戏。`A/D`（或左右方向键）选锚，`E` 传送，`M` / `Esc` 关闭。
- 房间首次清空后记为"已清"，本次单局不再刷新该房间妖物；藏酒密室的固定补给在一局内只拾取一次。传送不会重置房间的清空状态。
- 进入新房间有 0.16 s 淡出 + 0.16 s 淡入过场；房间标题在顶部短暂显示。死亡 1.6 s 后在余烬祠重开整局；`R` 随时重开。操作提示在开局显示 14 s 后淡出，避免长期遮挡地面。

#### 2.8.3 传送灯锚

- 第一关布置 7 座灯锚，分布在主要节点，便于回程与支路探索：

| 灯锚 | 房间 | 位置 | 初始状态 |
| --- | --- | --- | --- |
| 余烬祠灯锚 | `shrine` | 火龛东侧 | 开局自动点亮 |
| 客栈大堂灯锚 | `inn_front` | 大堂东段 | 靠近按 E 点亮 |
| 后院灯锚 | `backyard` | 后院东侧 | 靠近按 E 点亮 |
| 酒窖暗道灯锚 | `cellar_upper` | 藏酒密室门前 | 靠近按 E 点亮 |
| 岭口岔路灯锚 | `ridge_fork` | 五级跳台下方 | 靠近按 E 点亮 |
| 药王谷灯锚 | `valley_gate` | 谷口中段 | 靠近按 E 点亮 |
| 寒山寺灯锚 | `temple_gate` | 山门中段 | 靠近按 E 点亮 |

- 未点亮的灯锚是冷灰石座灯盏；靠近时显示"E 点亮灯锚"。点亮后出现暖色光晕与火焰摆动，并显示"灯锚已亮"提示；再次靠近按 E 可直接打开舆图。
- 每座灯锚的落点在灯盏左侧，传送后角色自动面向灯锚；落点已校验不与出口、墙体或机关重叠。
- 灯锚只在本局内有效：死亡、`R` 重开或返回余烬祠重开时，只有余烬祠灯锚保留，其余灯锚需重新点亮。该规则与"单局进度不存档"的 Roguelite 规则一致。
- 传送按 0.16 s 淡出 + 0.16 s 淡入执行，目标房间沿用原有的清空/补给/发现状态；灯锚交互与舆图传送均不会触发房间出口。

## 3. 美术与音频规格

### 3.1 分辨率与尺寸

| 项目 | 规格 |
| --- | --- |
| 内部渲染 | 480×270 |
| 窗口缩放 | 整数倍（2x = 960×540，3x = 1440×810，4x = 1920×1080） |
| 地块 | 16×16 |
| 玩家帧 | 52×40（当前占位；含兵器挥击空间） |
| 普通敌人 | 24×36（当前占位）；正式素材预留 32×32 / 48×48 |
| 精英 | 64×64 |
| Boss | 96×96 – 192×192 |
| UI 图标 | 16×16 / 24×24 |
| 像素缩放 | nearest-neighbor，禁止平滑 |

### 3.2 动画规范

| 动作 | 帧数 | 帧率 |
| --- | --- | --- |
| 待机 | 4–6 | 8–10 fps |
| 跑动 | 6–8 | 10–12 fps |
| 跳跃/下落 | 2–4 | 10 fps |
| 普攻 | 3–6 | 12–15 fps |
| 受击 | 1–2 | 15 fps |
| 死亡 | 6–8 | 10 fps |
| Boss 招式 | 6–12 | 12 fps |

### 3.3 调色板与风格

- 32–48 色限制，推荐 Endesga 32 / Apollo 等开源调色板。
- 武侠夜岭基调：竹海青绿、灯纸暖橙、月色冷白；角色轮廓用深色描边保证可读性。
- 像素素材关闭平滑与模糊；辉光用分层透明贴图实现。中文 UI 暂用系统字体抗锯齿渲染，正式版替换为可商用的像素中文字体。
- 所有素材统一光源方向（建议左上）。

### 3.4 音频规格

- BGM：`.ogg`，循环点标注，4 个区域各 1 首 + Boss 1 首 + 余烬祠 1 首（竹海用箫与雨声，客栈段加琵琶）。
- 音效：`.wav`，44.1kHz，短音效 < 0.5 s。
- 动态混音：Boss 战切曲，低血量滤波（后期）。
- 必需音效清单：跳跃、落地、冲刺、挥砍、命中、暴击、受击、死亡、拾取、开箱、技能、弹反、Boss 预警。

### 4.2 AI 素材使用原则

1. AI 只用于**概念探索与占位**，最终关键素材建议人工修整或重绘。
2. 统一调色板与像素密度，AI 输出常出现"伪像素"（分辨率不一致），必须后处理。
3. 不使用提示词模仿《死亡细胞》或其他具体游戏的独特美术风格与角色设计。
4. 商用前确认工具的商用授权条款；保留生成记录。
5. 所有第三方素材（字体、音效、音乐）建立 `assets/CREDITS.md` 记录来源与许可证。

### 4.3 素材命名规范

```text
<类别>_<对象>_<动作>_<序号>.<扩展名>

示例：
player_idle_01.png
enemy_rat_attack_02.png
boss_warden_phase2_roar_01.png
sfx_hit_light_01.wav
bgm_biome_cave_loop.ogg
```

- 全部小写 + 下划线；动画帧序号两位。
- 图集切分由 `tools/slice_sheets.py` 完成，避免手工导入错误。
